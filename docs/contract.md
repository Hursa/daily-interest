## 〇 · 这份文件是什么

**生产方和消费方之间唯一的约定。**两边各自怎么实现都行,但这里定的目录、文件名、字段、时序,谁都不能私自改。

改这份文件 = 改契约,**两边要同时跟**。所以每次改都要动 `schema` 号(见第五节)。

> **一句话:app 只信 `manifest.json`。**没有列在 manifest 里的文件,就当它不存在。

## 一 · 目录结构

```
daily-interest/
├── manifest.json                  ← 索引。app 每次先读它,而且只读它列出的东西
├── discover/
│   ├── 2026-08-05.json            ← 一天一个文件
│   ├── 2026-08-06.json
│   └── …
└── images/                        ← 可选。图走外链时这个目录不存在
    └── 2026-08-05/
        ├── kintsugi.jpg
        └── kintsugi-2.jpg
```

**只有这三样。**别的文件(README、脚本、日志)随便放,app 不看。

## 二 · `manifest.json`

```json
{
  "schema": 1,
  "updatedAt": "2026-08-05T07:04:31+08:00",
  "days": ["2026-08-05", "2026-08-04", "2026-08-03"]
}
```

| 字段 | | |
|---|---|---|
| `schema` | int | 契约版本。见第五节 |
| `updatedAt` | string | ISO 8601 **带时区偏移**。给人看的,app 不依赖它做逻辑 |
| `days` | string[] | **新 → 旧**排序。每一项必须对应一个真实存在的 `discover/<day>.json` |

### 写入时序是硬的

> **先写当天的 json,`git add` 之后,最后才更新 `manifest.json`,然后一次性 commit + push。**

顺序反了会出现这个窗口:manifest 说有 8月5日,但 `discover/2026-08-05.json` 还没推上去,**app 拉一个 404 下来**。

**一次 commit 里同时包含两者**,git 的原子性就替我们兜住了。

## 三 · `discover/YYYY-MM-DD.json`

```json
{
  "schema": 1,
  "date": "2026-08-05",
  "generatedAt": "2026-08-05T07:04:12+08:00",
  "items": [ … ]
}
```

### `items`

**至少 3 条,建议 4 条。**

> **app 显示前 3 条。第 4 条是备胎**——用户点了「这条不对」,就用它顶上。
> 没有备胎的话,当天会只剩两扇窗。

单条:

```json
{
  "id": "baishizhou-after",
  "scope": "深圳",
  "thesis": "城中村消失的速度和一个人重建生活的速度不匹配。",
  "title": "白石洲拆了以后,那些人搬去了哪",
  "body": "第一段。\n\n第二段。\n\n第三段。",
  "tryThis": "周末坐地铁到一个你从没下过的站,只在站点周边走两小时,不用导航。",
  "image": "https://upload.wikimedia.org/…/xxx.jpg",
  "inlineImages": [
    { "src": "https://upload.wikimedia.org/…/yyy.jpg", "after": 2 }
  ],
  "link": { "url": "https://…", "label": "去看看" },
  "category": "elsewhere",
  "tone": "质朴",
  "verifiedAt": "2026-08-05",
  "_facts": [
    { "claim": "白石洲拆迁涉及约 8 万租户", "source": "https://…" }
  ]
}
```

渲染出来是这个样子:

```
［深圳］白石洲拆了以后,那些人搬去了哪
城中村消失的速度和一个人重建生活的速度不匹配。

[正文]

→ 你可以试试:周末坐地铁到一个你从没下过的站,
  只在站点周边走两小时,不用导航。
```

### 字段

**给读者看的:**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `scope` | string | ✅ | 地域标签。app 渲染成 `［深圳］` 加在标题前。**取值见下「同心圆」** |
| `thesis` | string | ✅ | **一句副标题,20–40 字。**这一条最要紧:它让列表页的三选一有信息量,不再只有光秃秃的标题 |
| `title` | string | ✅ | 8–18 字。**不要把 `［深圳］` 写进 title**,那是 app 用 `scope` 拼的 |
| `body` | string | ✅ | 280–450 汉字。段落之间 `\n\n`,**不要 markdown** |
| `tryThis` | string | | 一句可做的事。**一天最多一条 item 带这个字段**,理由见下 |
| `image` | string | ✅ | 首图。见「图的两种形态」 |
| `inlineImages` | array | | 0–3 张。`after` = 插在第几段之后(**从 1 数**) |
| `link` | object \| null | | `{url, label}`。没有合适外链就 `null` |

**内部用的**(app 不显示,只给策展和校验):

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | kebab-case 英文。**跨天全局唯一**——app 用它记「看过 / 否掉」 |
| `category` | string | ✅ | `elsewhere` / `limits` / `twohours` / `mastery` / `stillrunning`。**保证题材不单一** |
| `tone` | string | ✅ | `质朴` / `有力` / `欢快` / `独特`。**每天至少一条 `欢快`** |
| `verifiedAt` | string | | `YYYY-MM-DD`,URL 校验通过的日期 |
| `_facts` | array | | `{claim, source}`,`source` **必须是能点开的 URL**。下划线开头 = 只给人审用 |

> **`scope` 是读者能读的,`category` 和 `tone` 是策展内部的。**
> 三个轴各有各的活儿:`scope` 管远近,`category` 管题材,`tone` 管情绪。
> **界面上只出现 `scope`**——另外两个一旦显示出来,就变成了在替读者标注该有什么感觉。

### 同心圆:`scope` 的取值

| 环 | 取值 | |
|---|---|---|
| **最内** | `深圳` / `连州` / `西安` | **你生活过的地方。**不只是现居地——存量宽得多,而且读到会多一层东西 |
| 中 | `中国` | |
| 外 | `全球` | |

**配比:一周里最内圈至少两条。**

> 不要求每天集齐三环。**一年 365 条有质量的深圳内容,存量撑不住**——白石洲这种能查证、有分量的题材，深圳一年找不出 365 个。
> 硬凑的结果是往里塞新闻,而那正是这一页拒绝的东西。

要加新的地名,改这张表,**不用升 `schema`**(app 是直接把字符串套进方括号,不做校验)。

### `tryThis`:一天最多一条

这条限制是硬的,理由值得写下来:

> **三条建议是三笔欠账,一条是一个邀请。**

而且稀缺让它更值钱——每天三条都有,你会开始略过。

**它必须当场做得完,不留尾巴。**

| | |
|---|---|
| ✅ | 「明早醒来先别碰手机,出门抬头看一眼天」——一次,几分钟,做完就没了 |
| ✅ | 「周末坐地铁到一个没下过的站,走两小时」——一个周末 |
| ❌ | 「这周挑一件你做到 100 分的事,只做到 70 分」——**这是一周的观察任务,它会跟着你一周**,那就是欠账的形状 |

**三条不做的:**

- **不打勾、不提醒、不问你做没做。**它和卡片一起在当天结束时消失
- **不进任何记录、不计分、不上树**
- **不做「今天的建议」列表**

**如果某条真的打动你,它的去处是「遇见」**——一键变成本周那件不可替代的事,或者进 10.6 的词库。

> **发现是入口,遇见是承接。建议之所以不积累,是因为它要么当场做掉,要么被你主动搬进遇见。**
>
> 这样 10.6 那条「推荐只能是你去够的,不能是它递过来的」也没破——**够的动作从「点开推荐」变成了「点这一条」**。

### 图的两种形态

`image` 和 `inlineImages[].src` 都接受两种值,**看开头判断**:

| 形态 | 例子 | app 怎么处理 |
|---|---|---|
| **外链**(推荐) | `https://upload.wikimedia.org/…` | 下载 + 本地缓存 |
| 仓库内 | `images/2026-08-05/kintsugi.jpg` | 相对**仓库根**,跟着内容一起拉 |

**默认走外链,首选 Wikimedia Commons**(公有领域、链接稳定)。理由:

> **git 历史永远不会缩。**一天 3 条 × 3 张 × 300KB ≈ 1MB/天,**一年 350MB,而且删了也拿不回空间**。

只在找不到合适外链、又非要有图的时候,才放进 `images/`。

### 三条内容侧的硬约束(实测踩出来的,别省)

1. **同一条里的两张图不能是同一张照片的不同裁切。**文件名不同、哈希不同,肉眼是同一张——2026-08 那批 30 条里 26 条中招
2. **图不能是纯色。**下载失败常常给回一张纯黑图。灰度标准差 < 6 就是它
3. **每个图 URL 提交前 `curl -sI` 验一次**:200 且 `content-type: image/*`

## 四 · 传输:app 怎么拿到

**格式和传输是分开的。**下面三条路,`manifest.json` + `discover/*.json` 的内容一个字都不用变。

| | app 需要凭据吗 | 本项目 |
|---|---|---|
| repo 公开,走 `raw.githubusercontent.com` | 不需要 | **不适用。**`Hursa/daily-interest` 是私有仓库 |
| **自己的服务器**(日记备份那台)镜像一份 | **不需要** | ✅ **本项目走这条。**基础设施已经在跑,图也有地方放 |
| repo 私有,app 带 token | 需要 | **不行。**iOS 二进制可以被提取,token 等于公开 |

> **2026-08-04 决议:仓库改为 `Hursa/daily-interest`,且保持私有。**
> 因为私有,raw 那条路直接作废——不是把 URL 里的 `dailylife` 换成 `daily-interest` 就行,
> `raw.githubusercontent.com` 对私有仓库返回 404,不带 token 拿不到任何东西。
> 所以**唯一可用的是镜像那条**:服务器上 clone 这个私有 repo、定时 pull,再以 HTTP 对外暴露。

镜像基址(**待定,填好后回来补**):

```
https://<你的服务器>/discover/manifest.json
https://<你的服务器>/discover/2026-08-05.json
```

生产侧不受影响:定时任务照样只往 git 里写,`manifest.json` + `discover/*.json` 的内容一个字不变。

### app 侧行为(交给 Codex)

1. **进前台时拉 `manifest.json`**,带 `If-None-Match`(GitHub raw 给 ETag),304 就什么都不做
2. 对比 `days` 和本地已有的,**只拉缺的那几天**
3. 落到 `Application Support/discover/`,**不是 Bundle**
4. 图按需下载,存 `Caches/`(可以被系统回收,回收了重下)
5. **拉不到就用本地缓存,静默失败**——不弹错、不提示、不重试轰炸。第六节是零通知的
6. **本地只留最近 30 天**,更早的删掉

### 仓库侧保留窗口

`discover/` 里**保留最近 90 天**,更早的从 `manifest.days` 里摘掉并删文件(git 历史里还在,想回溯随时能翻)。

## 五 · `schema` 版本

现在是 `1`。

- **加可选字段** → 不动版本号。app 忽略不认识的字段
- **改字段含义 / 加必填 / 删字段** → **`schema` +1**,而且**两边同时上线**

**app 遇到 `schema` 比自己认识的大**:跳过那个文件,用旧的缓存,不崩。

## 六 · 一天的时序

```
07:04  定时任务跑
       ├─ 读 manifest.days,grep 最近 14 天题材,避重
       ├─ 选题 → 写 4 条 → 自查(spec 第六节那 10 条)
       ├─ 校验每个图 URL:200 + image/*
       ├─ 写 discover/2026-08-05.json
       ├─ 更新 manifest.json(days 头部插入,尾部超 90 天的摘掉)
       └─ git add discover/ manifest.json && commit && push   ← 一次 commit

任意时刻  app 进前台
       ├─ GET manifest.json(If-None-Match)
       ├─ 304 → 结束
       └─ 200 → 拉缺的日期 → 存本地 → 显示当天前 3 条
```

**app 显示哪一天:**按设备本地日期取 `discover/<今天>.json`。取不到就往前找最近的一天——**宁可显示昨天的三扇窗,也不要显示空页**。

## 七 · 生产方要改的(如果用的是我之前给的那份 prompt)

| 之前写的 | 改成 |
|---|---|
| `imageURL` | **`image`** |
| `inlineImageURLs: ["…"]` | **`inlineImages: [{"src":"…","after":2}]`** |
| 每天 **3** 条 | 每天 **4** 条(第 4 条是「这条不对」的备胎) |
| —— | **新增 `scope`**,取值见第三节「同心圆」 |
| —— | **新增 `thesis`**,一句 20–40 字的副标题 |
| —— | **新增 `tryThis`**,可选,**一天最多一条** |

字段名沿用 app 现有的 `image` / `inlineImages`,**不是为了好看,是为了 Codex 那边只用把取值从「本地路径」放宽成「路径或 URL」,模型结构一行不用动**。

### `thesis` 怎么写

它不是摘要,是**这篇的论点**。

| ✅ | 「城中村消失的速度和一个人重建生活的速度不匹配。」 |
| ❌ | 「本文讲述白石洲拆迁后原住户的去向。」 |

差别:前者是一个判断,读完标题+它你就知道要不要点;后者只是把标题又说了一遍。

**它同时替掉了原来那条「结尾落到什么样的生活会长出这个东西」的位置**——那句话提到最前面来了。所以正文结尾**照旧不要抒情、不要给教训**,最后一句仍然必须是一个可核实的事实。

## 八 · 给 Codex 的改动清单

**取数**

1. `DiscoverLibrary.loadNewest()` 现在从 **Bundle** 读 `discover-*.json`。改成从 **Application Support** 读 `<yyyy-MM-dd>.json`,Bundle 那份留作首次安装的兜底
2. `DiscoverLibrary.imageURL(path:)` 现在只拼 Bundle 路径。改成:**`http` 开头 → 远端下载 + 缓存;否则按仓库内相对路径**
3. 新增拉取:`manifest.json`(带 `If-None-Match`)→ 差量拉缺的日期 → 落盘 → 只留 30 天。**拉不到静默用缓存**,不弹错不提示
   - **基址是自建镜像,不是 `raw.githubusercontent.com`**(仓库私有,raw 拿不到)。基址待定,见第四节
4. `DiscoverBatch` 加 `schema`,大于已知版本就跳过那个文件用缓存,不崩

**挑选**

5. `DiscoverSessionStore.prepare(batch:)` 现在从大批次里按天挑 3 条。**新模式下当天文件就是当天内容,不用再挑**——取前 3 条,`reject` 时用第 4 条顶上

**渲染**(三处新的)

6. **`［scope］` 拼在标题前**,列表页和详情页都要。方括号用全角 `［］`,和示例一致
7. **`thesis` 当副标题**,列表页在标题下面显示一行(**这是这次改版最重要的一处**——原来列表页三张卡只有光秃秃的标题,选不动)
8. **`tryThis` 放正文最末**,前面加 `→`。样式要比正文轻一档,**不要做成按钮、不要做成卡片**——它是一句话,不是一个任务
   - 旁边给一个**「加进遇见」**的入口:点了就把这句话变成本周那件不可替代的事(或者进 10.6 的词库)
   - **不打勾、不记录、不提醒。**它和卡片一起在当天结束时消失

第 8 条那个「不做成按钮」是有理由的:**做成按钮它就变成了一个待办**,而这一页明确不产生待办。见第三节 `tryThis` 那一小节。
